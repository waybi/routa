# 最佳实践

## 从最小够用的模式开始

优先使用 [Sessions](/use-routa/sessions)，除非你已经明确知道自己需要看板策略或团队协作。

## 先配置一个能跑通的 Provider

不要在一开始就把所有 Provider、模型和角色默认值全部塞进来。只要有一条能真正执行工作的 Provider 路径，就足以顺利起步。

## 让工作保持工作区作用域

把工作区当作主要的运行边界。仓库、会话、任务和自动化都应当附着在该工作区上，而不是依赖隐式的全局状态。

## 用看板支撑可重复的交付

如果你想要清晰的评审边界、明确的产物预期以及可见的交接，就把工作迁移到 [Kanban](/use-routa/kanban)，而不是试图在单个会话里模拟这一流程。

## 仅在协作确有必要时使用团队

当多个专长方向确实需要协同工作时，才使用 [Team](/use-routa/team)。不要对简单的实现任务默认就上团队模式。

## 让参考材料远离关键路径

用户在需要产品规格、设计文档或深度参考材料之前，就应当能完成第一次有用的运行。这正是 [Getting Started](/getting-started) 和 [Use Routa](/use-routa) 应当比内部仓库文档更简单的原因。
