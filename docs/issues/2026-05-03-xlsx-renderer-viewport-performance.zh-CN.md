# XLSX 渲染器需要生产级的视口性能

## 解决方案 - 2026-05-04

针对当前的调试查看器以及与 Walnut 对齐的架构边界，本问题已解决：

- 工作簿/工作表派生的布局、图表、形状、图片、表格视觉、条件格式规则、数据验证范围、迷你图、批注以及切片器回退，现在都会被记忆化（memoize）或延迟解析，而不是在每次滚动时重建
- 可见的行/列范围通过前缀和与二分查找计算；正文单元格、表头、冻结区域以及浮动覆盖层只渲染当前活动视口加上 overscan 的部分
- 滚动/尺寸更新通过帧合并（frame-coalesced）的视口存储以及纯渲染快照适配器流转
- 预览会挂载一个 canvas 层，配合稳定的绘制计划、requestAnimationFrame 调度、计划签名跳过，以及在浏览器支持时使用 worker/offscreen canvas 传输
- canvas 绘制命令现在携带可见单元格的文本、填充和字体颜色，为生产级渲染器提供了稳定的非 DOM 契约，同时保留当前的 DOM 网格以支持丰富的编辑和覆盖层行为
- 已提交的 XLSX 固件以及 `/Users/phodal/Downloads/excel` 中仅用于验证的 21 文件语料库，在视口工作完成后仍然通过解码后的 Walnut 协议一致性校验

后续的性能工作应作为基准测试覆盖或产品化来跟踪，而不是作为本问题中尚未解决的布局/性能阻塞项。

## 发生了什么

XLSX 读取器现在在固件套件以及 `/Users/phodal/Downloads/excel` 中仅用于验证的生产语料库上都与 Walnut 解码后的 Workbook 协议匹配，但调试预览仍然使用 React DOM 节点来渲染电子表格单元格。这对于当前的 POC 和受限布局来说是可以接受的，但随着行/列上限被提高以及更多工作表覆盖层被启用，它可能变得开销很大。

## 预期行为

查看器应在不强制每个滚动事件都经历昂贵的 React 工作的前提下，保持类似 Walnut 的视口语义：

- 稳定的布局、图表、图片、形状以及条件格式规格应按工作簿/工作表变化记忆化，而不是按滚动变化
- 可见单元格的渲染应限制在当前视口加上 overscan 的范围内
- 冻结窗格只渲染可见的冻结区域
- 大型工作表最终能够将基础网格绘制迁移到 canvas 或 worker 支持的 canvas，而不改变工作簿协议契约

## Walnut 参考

Walnut 提取出的 `PopcornElectronWorkbookPanel-BZz8NPb4.js` 将工作簿渲染视为对性能敏感的视口：

- 工作簿几何信息以 `columnWidths` 和 `rowHeights` 存储
- 前缀和将逻辑工作表坐标映射到屏幕/相机坐标
- 冻结窗格、选区、浮动元素、图表悬停目标以及调整大小的手柄共享同一坐标系
- 更新路径通过 controller/worker 边界路由，并以基于帧的调度进行合并
- canvas 支持的图表与工作表交互避免了完整的 DOM 表格布局

## 当前 Routa 状态

- `src/app/debug/office-wasm-poc/spreadsheet-layout.ts` 已经提供了前缀和、二分查找的可见范围查询、冻结窗格投影、浮动命中区域以及绘制边界。
- `src/app/debug/office-wasm-poc/spreadsheet-preview.tsx` 在可滚动网格中只渲染可见单元格和可见的浮动覆盖层。
- `src/app/debug/office-wasm-poc/spreadsheet-frozen-headers.tsx` 从同一视口范围渲染可见的行/列表头，而不是映射每一行和每一列工作表。
- 滚动驱动的视口状态通过 `requestAnimationFrame` 合并，匹配 Walnut 基于帧调度的更新方式，而不是为每个滚动事件更新 React state。
- 表格、条件格式、数据验证、迷你图、批注、图片、形状以及图表覆盖层现在要么按工作簿/工作表变化记忆化，要么按可见单元格延迟解析。

## 进展

- 在解码后的 XLSX 协议一致性达到与 Walnut 在全部 21 个仅用于验证的生产工作簿上字段级差异为 `0` 后，创建了本跟踪记录。
- 在调试电子表格预览中记忆化了根工作簿派生、活动工作表布局、图表规格、形状规格、图片规格以及条件格式视觉，使滚动更新不会重建稳定的工作簿派生结构。
- 将冻结正文覆盖层改为复用可见视口范围以及合并起点的 overscan 逻辑，而不是遍历当前布局中的每一行/列。
- 为浮动图片、形状以及图表覆盖层添加了视口/overscan 裁剪，使屏幕外的绘图在滚动期间不会挂载 canvas 或 DOM 节点。
- 使用 `requestAnimationFrame` 合并电子表格视口的滚动/尺寸更新，使滚动处理更接近 Walnut 基于帧的视口调度。
- 移除了仅用于调试的 80 行 / 32 列布局上限。布局适配器现在保留完整的 Excel 规模行/列边界，而正文和表头只渲染活动视口窗口。
- 添加了使用 Walnut 规模演示尺寸（`1500` 行、`182` 列）的生产规模布局回归测试，以锁定完整布局 + 小视口的行为。
- 重做了条件格式视觉计算，使其一次性构建工作表行/单元格索引并在各次范围扫描中复用，避免为大型条件格式范围反复构建完整工作表映射。
- 将表格样式视觉从急切的完整表格物化改为延迟查找模型。表头/筛选、条纹、边缘列以及合计的样式现在按需为可见单元格解析，而不是为每个表格单元格分配视觉条目。
- 将条件格式视觉改为同样的延迟查找模型。色阶、数据条、图标集、文本/单元格规则以及已知的回退规则现在保留紧凑的规则规格加上范围统计信息，仅为可见单元格解析。
- 将条件格式的数值范围扫描改为遍历已填充的工作表单元格并按范围筛选，避免在稀疏的整列/整表规则上进行密集迭代。空单元格现在保持非数值，而不是被当作 `0` 处理。
- 添加了对绝对、限定工作表、整列以及整行引用（例如 `$A$1:$B$2`、`Sheet1!A:A` 和 `1:1`）的 Excel 风格范围解析，使生产环境的条件格式/表格范围能够扩展到工作表边界，而无需密集的视觉物化。
- 为延迟的表格/条件查找添加了有界的单元格视觉缓存，使得重复的正文/冻结渲染不会在滚动时为相同的可见单元格重新扫描规则，同时滚动也无法让缓存无限增长。
- 在延迟查找/范围解析更改后，使用 `--assert` 验证了固件协议一致性、固件渲染契约、图表密集型渲染契约，以及 `/Users/phodal/Downloads/excel` 下的 21 文件生产 XLSX 语料库；全部针对 Walnut 通过。
- 扩展了 `test:office-wasm-reader:xlsx-render` 以包含 `xlsx_multi_chart_contract.xlsx` 和 `xlsx_surface_chart_contract.xlsx`，使常规渲染检查现在覆盖多图表和曲面图的协议/布局契约。
- 隐藏的行和列现在在前缀和布局中保留为零尺寸条目，匹配 Excel/Walnut 的视口语义，而不会移动后续的行/列索引。
- 行和列的 `styleIndex` 值现在在布局适配器中得到保留，并在单元格没有直接样式时参与渲染器的样式/数字格式回退。
- 内置的 Excel 数字格式现在参与单元格文本渲染，覆盖常见的日期、百分比、小数、千分位以及货币 `numFmtId` 值，即使不存在自定义的 `numberFormats[]` 条目。
- `showGridLines=false` 现在在调试预览中抑制回退的工作表网格线边框，同时保留显式的单元格边框颜色。
- Excel 对齐标志现在为视口渲染器提供常见的水平/垂直对齐、抑制换行、缩小以适应以及缩进样式。
- 显式的单元格边框颜色、线型以及常见的 Excel 边框宽度现在映射到视口渲染器，而不是总是回退到细的实线网格线。
- 内置数字格式现在覆盖常见的科学计数、分数、经过时间/时钟时间，以及负数分节的数字/货币格式。
- 图表绘图区布局现在尊重非覆盖式的上/左/右/下图例空间，而覆盖式图例不再缩小绘图区。
- 图表 y 轴刻度标签现在使用常见的轴数字格式来显示百分比、货币、固定小数以及千分位。
- 折线图系列标记现在由协议驱动，而不是为每个系列强制启用；回退的演示图表仍然选择启用标记。
- 工作表的 `sparklineGroups` 现在根据协议范围渲染为每单元格内联的 SVG 迷你图，支持折线/柱形/堆叠类型、系列颜色、线宽以及标记标志。
- 被 XLSX 批注或线程化批注线程标记的单元格现在在视口中右上角渲染一个轻量级批注指示器。
- XLSX 数据验证范围现在使用延迟的有界查找，并为可见单元格渲染列表下拉框或验证指示器，包括无需密集物化的整列范围。
- 工作簿工作表的 `tabColor` 值现在为底部工作表标签页装饰提供数据，而不是被预览忽略。
- 工作表级别的切片器协议对象在没有任何绘图形状已表示该切片器时，现在会获得一个回退的工作表覆盖层。
- 条件格式预览解析现在覆盖 `stopIfTrue`、常见的文本/单元格比较、重复/唯一规则、前/后规则，以及高于/低于平均值规则，而不会回到急切的完整工作表视觉物化。
- 公式驱动的条件格式规则现在对常见表达式使用保守的求值器，而不会增加急切的完整工作表渲染。
- 数据条渲染现在从既有的延迟条件格式查找中使用 `showValue`、`direction`、`minLength` 和 `maxLength`。
- 通过电子表格冻结表头、图表和形状单元测试，以及针对 `spreadsheet-preview.tsx` 的定向 ESLint，验证了这次低风险的视口处理。

## 残留的后续工作

- 在不提交生产文件的前提下，为更大的工作表添加合成压力固件和基准数据。当前的验证语料库证明了协议一致性，但它并不衡量持续的滚动/调整大小/编辑器负载。
- 为大型可见范围、密集的表格/条件格式/数据验证规则、迷你图组、绘图覆盖层、冻结窗格分段以及反复的滚动更新添加显式的性能门槛。当前测试锁定的是行为，而不是运行时预算。
- 如果 XLSX 预览成为产品界面，应继续将更丰富的格式化、覆盖层绘制、指针悬停目标以及编辑器视觉迁移到 canvas/worker 绘制计划路径。适配器应保持作为列/行前缀和、冻结窗格、浮动命中区域以及覆盖层几何信息的契约边界。
- 将 `/Users/phodal/Downloads/excel` 保留为仅用于验证的输入。未来任何压力语料库都应是生成的合成数据或小型已提交固件，避免使用客户/生产内容。
