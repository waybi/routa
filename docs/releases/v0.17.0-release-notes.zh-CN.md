# v0.17.0 AI 摘要

## 亮点

- **Feature Explorer 成为本次发布中最主要的新界面。** 现在产品在 Web 端和 Rust 后端都提供了更加丰富的「特性优先（feature-first）」信息架构，包括路由树导航、界面索引（surface index）浏览模式、特性指标、仓库切换、会话分析抽屉、相关文件列表，以及学习得到的提示词上下文摘要。

- **会话与 Trace 分析能力显著增强。** 特性追踪（feature tracing）被迁移到专用 crate 和解析器中，transcript/会话发现变得更加稳健，Explorer 现在能够将选中的文件、路由、界面和提示词信号关联回真实会话，并在不同运行时之间实现更好的一致性（parity）。

- **Harness、适应度函数（fitness）与发布相关操作得到了收紧与完善。** 本次范围包括图感知（graph-aware）的测试映射快照、由 pi-autoresearch 驱动的适应度函数速度优化、release-skill 准备流程、仓库级共享 skill 约定，以及若干验证、可移植性和 pre-push 稳定性修复。

- **Team、Spec、Canvas 和 MCP 等界面同步推进。** Team 运行界面在 Rust/后端一致性方面得到改善，Spec 区域演进为带 Harness 集成的本地 issue 可视化看板，canvas/sdk 资源成为可在不同运行时之间共享的一等 MCP 工件。

## 值得关注的领域

- `feature-explorer`：在布局、信息架构（IA）、后端一致性、feature-tree 摄取、会话分析、分类法推断，以及学习得到的提示词上下文等方面进行了大幅扩展
- `harness` / `entrix`：速度优化、图感知映射快照、验证后续工作，以及发布准备工作流
- `team`：后端 team-run 界面一致性、防环（cycle-safe）的后代计数、本地化的未命名运行处理，以及 lead-specialist 标记
- `spec` / `canvas` / `mcp`：本地 issue 可视化看板、canvas SDK 资源、受约束的 React 运行时工件，以及跨运行时契约共享

## 发布形态

本次发布偏重于功能特性，而非补丁集合。与 `v0.16.0` 相比，其范围主要由 Feature Explorer 计划主导，并辅以适应度函数自动化、后端一致性、issue/spec 工具，以及发布体验等方面的改进。
