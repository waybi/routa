# 发布 v0.14.0 — AgentWatch、Codex 运行时稳定性与工作流清晰度

**发布日期**：2026-04-10  
**标签**：`v0.14.0`

## 概述

Routa Desktop v0.14.0 专注于让日常的多 Agent 执行更可观测、更可靠。

本次发布引入了 AgentWatch，作为以 TUI 为先的本地运行时，用于在单个仓库内跟踪实时编码 Agent 活动；强化了 Rust/桌面端路径上的 Codex 与 MCP 集成；厘清了 Sessions/Kanban/Team 三种执行模式；并在就绪门控（readiness gate）、看板交互和工作区导航等方面改进了看板交付体验。

相较于 `v0.13.0`，本次发布包含 130 个非合并提交，并在 `agentwatch`、ACP/MCP 运行时接线、看板流程控制以及工作区外壳简化方面投入了大量工作。

## 核心亮点

### 1. AgentWatch 成为一流的本地操作界面

- 新增 `agentwatch` crate，并将 TUI 运行时设为默认体验
- 引入由 Codex 钩子、git 钩子和仓库扫描驱动的实时会话与文件归属
- 新增实时文件预览、语法高亮的 diff、事件日志过滤、主题切换以及响应式 TUI 布局
- 新增本地运行时传输与 `serve` 模式，并可回退到仓库范围的 feed 传输
- 改进了已检测 Agent 的建模、会话关联、未知会话处理以及手动归属的持久化

用户影响：
- 你无需离开终端，即可看到哪个 Agent 处于活动状态、它正在改动哪些文件，以及最近发生了什么变更
- 在长时间运行的编码会话中，脏工作树（dirty worktree）状态和跨会话归属更易于检查
- 当钩子、会话与 git 活动之间出现失步时，本地多 Agent 工作更易于调试

### 2. Codex、ACP 与 MCP 运行时行为更稳定

- 修复了 Rust 运行时路径上项目范围的 Codex MCP 配置注入
- 将 Routa MCP 服务器注入到 Codex 会话中，并将 Codex MCP 叠加层隔离在 Routa 之下
- 在 Rust 侧将 MCP 服务处理切换为 RMCP 可流式 HTTP（streamable HTTP）
- 在 Rust SSE 流程中正确合并重放分块（replay chunk），并改进了 turn 完成后的 Trace 恢复
- 在 Provider 启动前校验会话工作目录，并恢复了 MCP 制品（artifact）的一致性

用户影响：
- 基于 Codex 的会话能更一致地在预期的工作区上下文中启动
- 跨桌面端会话时，MCP 工具可用性更可靠
- 在重连或长时间、工具密集的 turn 之后，流式回复和重放的会话历史行为更可预期

### 3. 看板交付流程更清晰、更可操作

- 在看板流程中直接呈现结构化的故事就绪阻塞项（story-readiness blocker）
- 将就绪状态更新暴露给泳道工具，并在满足门控时引导专家（specialist）使用 `update_task`
- 恢复了看板与工作区的回退机制，使看板导航更具韧性
- 将看板拖放迁移至 `dnd-kit`
- 新增 VS Code 风格的看板状态栏，并收紧了卡片/详情密度以加快扫读

用户影响：
- 当某张卡片尚未就绪、无法推进时，评审门控和完成门控更易于理解
- 看板交互体验更稳定，尤其是在桌面端模式和跨工作区导航时
- 高密度的看板视图承载了更多运营信号，而无需迫使用户进入大量模态框（modal）流程

### 4. 工作区入口与执行模式更易于理解

- 在首页界面厘清了三种主要执行模式：Sessions、Kanban 和 Team
- 将首页输入框更直接地连接到看板规划流程
- 用自定义菜单重做了工作区切换，并从页头移除了过时的计划-待办（plan-backlog）功能项
- 将首页简化为以启动器为先的界面，并使更多屏幕以会话作为默认恢复界面进行对齐
- 将全局设置控件移入外壳页头，并收紧了侧边栏/设置行为

用户影响：
- 新用户和回访用户可以更少歧义地选择合适的编排模式
- 从首页界面启动工作更直接
- 桌面端外壳在工作区、会话、看板和设置等屏幕之间的体验更一致

### 5. 聊天、引导（onboarding）与外壳打磨消除了常见的摩擦点

- 在工具调用和已完成的 turn 之间更干净地拆分 Codex 分块
- 在 turn 完成后重新水合（rehydrate）Trace，并移除了折叠思考态遗留的幽灵间距
- 在创建工作区后保持仓库设置可见，并在引导过程中隐藏无效的仓库状态
- 优化了 Team Run 切换与会话恢复行为
- 修复了围绕侧边栏持久化、设置高亮和会话菜单的若干外壳状态不一致问题

用户影响：
- 在流式或工具密集的 turn 之后，会话历史更值得信任
- 引导流程更不易在错误的时机隐藏下一步操作
- 常见的桌面端外壳交互不再那么脆弱

## 技术摘要

本次发布中值得关注的实现领域：

- `crates/agentwatch/`：新的本地 TUI 运行时、钩子集成、运行时传输和归属模型
- `crates/routa-core/src/acp/` 和 `crates/routa-server/src/api/mcp_routes/`：Codex/MCP 注入、RMCP 处理和运行时修复
- `src/app/workspace/[workspaceId]/kanban/` 和 `src/core/kanban/`：就绪门控、状态栏布局和看板交互更新
- `src/app/page.tsx`、`src/client/components/home-input.tsx` 以及工作区外壳组件：执行模式清晰度和启动器流程变更
- `docs/design-docs/agentwatch-tui.md` 和 `docs/design-docs/execution-modes.md`：新界面背后归一化的产品意图

## 升级说明

- 在该提交范围内未标记明确的破坏性变更。
- 如果你依赖 Codex 会话、MCP 工具注入或看板交付门控，桌面端用户应当升级，因为这些领域获得了最大量的稳定性修复。
- 对仓库级实时监控感兴趣的用户，可以借助本仓库中已有的仓库本地 Codex 钩子设置，试用全新的 AgentWatch 流程。
