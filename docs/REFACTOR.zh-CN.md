# 重构手册（Refactor Playbook）

本文档定义了 Routa.js 中针对大文件和热点（hotspot）清理的重构规则。

## 核心规则

1. 每次重构都以 `entrix` 分析开始，然后基于证据而非直觉来确定范围。
2. 优先处理超出预算的文件。预算内的文件属于次要，除非它们与某个活跃的 bug 或功能相关联。
3. 对于超大文件，应将逻辑从源文件中抽离，而不是在其内部添加更多分支。
4. 抽取时使用概念边界和工作流聚类；不要按任意行号范围拆分。
5. 先为目标抽取模块编写测试，然后再迁移逻辑。在行为被覆盖之前不要迁移。
6. 优先选择 ROI 最高、风险最低的拆分：每一轮只抽取一到两个高耦合模块，再考虑更大范围的分解。

## 分析优先工作流

在修改代码之前先运行这些命令：

```bash
entrix analyze long-file --json
cargo run -q -p routa-cli -- harness budget --config docs/fitness/file_budgets.json --changed-only --base "${ROUTA_FITNESS_CHANGED_BASE:-HEAD}"
cargo run -q -p routa-cli -- harness budget --config docs/fitness/file_budgets.json --changed-only --base "${ROUTA_FITNESS_CHANGED_BASE:-HEAD}" --overrides-only
```

分诊（Triage）顺序：

1. 存在预算违规的文件。
2. 在违规文件中，优先处理超出预算增量更大的文件。
3. 如果仍然相同，则优先处理 `entrix analyze long-file` 历史信号中变更较多的文件（例如 `commitCount`）。

## 测试优先抽取规则

在将任何代码块从长文件中迁移之前：

1. 创建或扩展特征测试（characterization tests），锁定被抽取代码块的当前行为。
2. 将测试放在新目标模块边界周围，而不仅仅是放在旧的单体文件上。
3. 确认当行为发生变化时测试会失败，而对于当前行为基线则会通过。

只有在这些检查通过之后，才将逻辑迁移到新文件中。

## 概念聚类策略

在选择抽取内容时，按概念和生命周期进行分组：

- 一次只处理一个工作流边界（例如 bootstrap、导航、会话编排、流式同步）。
- 将顶层路由/页面文件保持为编排外壳（orchestration shell）。
- 当真正的复杂性来自某个具体分支或工作流时，避免创建通用的 `utils` 集合。
- 优先在每次提交中进行一次内聚的抽取，而不是大范围的混合重写。

## 迁移顺序（默认）

1. 确定一个超出预算的文件和一个要抽取的聚类。
2. 先添加目标模块测试。
3. 创建具有明确接口的目标模块。
4. 迁移一个内聚的逻辑聚类。
5. 保持入口文件的行为和 API 形态稳定。
6. 删除死代码，并重新运行测试/lint/适应度函数检查。

## 完成标准

只有当以下所有条件都满足时，重构才算完成：

1. 抽取后的行为已在新边界处由测试覆盖。
2. 现有行为没有回归。
3. 文件预算压力已降低（或至少对于遗留的冻结热点没有恶化）。
4. 顶层文件作为编排外壳更加简洁，而不只是重新分布了复杂性。
