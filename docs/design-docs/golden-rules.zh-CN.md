# 黄金法则

这些法则定义了在 Routa.js 中进行 agent 优先（agent-first）开发所期望的最低仓库卫生标准。

## 文档法则

1. 将持久性知识放入 `docs/`，而不是聊天记录或臃肿的 `AGENTS.md` 散文中。
2. 为每一类知识保留唯一的规范归属地。
3. 创建新的持久性文档区域时，更新相应索引。
4. 优先采用短小、稳定的文档，而不是冗长、混杂多种用途的笔记。
5. 迁移旧材料时，保留其来源出处，并避免产生并行副本。

## 架构法则

1. 将 `docs/ARCHITECTURE.md` 视为顶层架构契约，除非某个更聚焦的规范文档取代了它的某个小节。
2. 保持双后端语义对等（dual-backend semantic parity），除非有意的偏离已被记录在案。
3. 优先采用明确的系统边界和契约，而不是隐式行为。
4. 在可能的情况下，将反复出现的架构约束编码为代码检查。

## 交付法则

1. 在编码之前，将庞大的史诗（epic）拆解为实现规模的计划。
2. 当问题并不简单时，在修复之前或与修复同时，将故障记录在 `docs/issues/` 中。
3. 让执行计划保持短期存活，并在交付完成时将其移入 `completed/`。
4. 优先采用能减少漂移的小步（baby-step）变更，而不是大规模的投机性重组。

## Agent 可读性法则

1. 使用具有描述性的文件名和直接的路径。
2. 使用描述意图的标题，而不是含糊的主题。
3. 将可执行的约束放在文档靠前的位置。
4. 避免在同一文件中混杂规范性指导、头脑风暴和历史笔记，除非各小节有清晰的分隔。

## 强制执行方向

某些法则当下属于社会性约定，并应随时间推移变得机械化（可自动强制）。

候选的后续检查：
- 检测新建持久性文档区域缺失的 `docs/` 索引链接
- 检测对已迁移规范文档的过期引用
- 检测在未保留来源出处的情况下被复制进 `docs/` 的遗留 `.kiro/specs/` 副本
- 将文档新鲜度和架构覆盖度纳入适应度函数（fitness）评分
